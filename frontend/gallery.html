Design spec

Every value on this page is read live from tokens.css at load time, not copied into the markup. If a token changes there, this page changes with it, and if a token is deleted its row here goes blank. That is deliberate: a spec sheet that restates values eventually lies about them.

Components below are rendered with the real stylesheets (panel.css, home.css, how-to.css), so what you see is what ships.

Color

One violet accent against a dark neutral ramp deliberately close to YouTube's, so the app reads as something sitting beside a player rather than a separate site. Accent carries weight and state; it is never decoration.

Elevation

Height is expressed two ways at once: a shadow underneath, and a one-pixel highlight along the top edge where light would catch a glossy surface. The highlight is never used alone. On its own it reads as a flat element with a stray line on it.

Motion

The part that decides whether this feels fluid or mechanical. Two rules. First, match the curve to the distance: something moving a pixel on hover wants --ease-standard, something crossing the panel wants --ease-glide, which decelerates through most of its travel and settles rather than stopping. Second, spend the budget unevenly. Most transitions should be quiet and quick, with the long curves and --ease-spring reserved for the few moments that carry meaning. Uniform motion is why the current pages feel flat: everything moves the same amount at the same speed, so nothing stands out.

Curves
All four run at --dur-slow so only the curve differs.
Durations
All five run on --ease-standard so only the duration differs.
Shorthands

Compose transitions from these rather than restating a duration and curve pair. transition: transform var(--motion-hover), not transition: transform 160ms cubic-bezier(...).

Lift

Named hover displacement, so no component invents its own nudge distance. Hover each square.
